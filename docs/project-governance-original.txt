## PHASE 4 — DEVELOPMENT, STAGING, AND PRODUCTION

Establish three distinct operational contexts.

### Development

Purpose: Build and modify the application.

- Runs locally.
- Uses development configuration.
- Allows rapid iteration.
- Does not affect production data.
- Can preview changes before committing.

### Staging / Test Mode

Purpose: Validate the application before launch.

- Uses the same application code.
- Has a separate staging URL.
- Has isolated databases and authentication.
- Uses payment-provider test mode.
- Uses safe test-only email delivery.
- Contains fictional test accounts and records.
- Supports automated end-to-end testing.
- Displays a visible TEST MODE indicator.
- Cannot charge real payment methods or initiate real-world fulfillment.

### Production / Live Mode

Purpose: Serve actual users.

- Uses the approved production domain.
- Uses protected production databases and credentials.
- Receives only explicitly authorized releases.
- Never serves unapproved experimental code.
- Has a documented rollback procedure.

**Do not create three separate codebases. Use one repository with isolated environment configurations.**
